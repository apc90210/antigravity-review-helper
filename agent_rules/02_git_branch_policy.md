# 02 — Git Branch Policy

## 1. Base branch

Default base branch:

```text
origin/develop
```

Before creating a feature branch:

```powershell
git fetch origin
git checkout develop
git pull --ff-only origin develop
git status --short --untracked-files=all
```

If develop is not clean, stop and report.

## 2. Branch naming

Use descriptive branches:

```text
feature/<area>-<stage>-<purpose>
```

Examples:

```text
feature/mvp-v1-odds-timestamp-strict-prematch-audit
feature/mvp-v1-strict-prematch-storage-schema-draft
feature/site-public-cosmetic-display-cleanup
feature/antigravity-parallel-workflow-protocol
```

## 3. Commit policy

Commit only intentional files.

Before commit:

```powershell
git diff --name-status
git diff --cached --name-status
git status --short --untracked-files=all
```

Do not include:

```text
- scratch files
- debug files
- cache files
- local reports outside expected directories
- credentials
- temporary scripts unless explicitly required
```

## 4. Push policy

Worker branches may push only their feature branch:

```powershell
git push origin feature/<branch-name>
```

Forbidden for worker agents:

```powershell
git push origin develop
```

## 5. Merge policy

Only an Integration Agent may merge.

Merge requirements:

```text
- acceptance report says READY_FOR_MERGE
- feature branch clean
- develop clean
- origin/develop current
- no forbidden files
- targeted tests pass
```

## 6. Submodule / nested repository policy

If `betsline/` is a nested repository or submodule:

1. Check its branch.
2. Check its status.
3. Do not change nested pointer unless task explicitly allows it.
4. If nested pointer changes unexpectedly, stop and report.

Commands:

```powershell
git submodule status
git -C betsline branch --show-current
git -C betsline status --short --untracked-files=all
git -C betsline rev-list --left-right --count origin/develop...HEAD
```

## 7. Forbidden broad cleanup

Do not run:

```powershell
git clean -fd
git reset --hard
```

unless the prompt explicitly authorizes exact paths and explains why.

Allowed cleanup is targeted:

```powershell
Remove-Item path\to\known_temp_file.py
```

Only if the file is known to be generated by the current task.
